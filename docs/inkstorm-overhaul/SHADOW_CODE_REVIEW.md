## Findings and fix status

1. **P1 — Do not publish a framebuffer that failed GPU allocation.** Initially `InkstormSunShadow.update` only treated JavaScript exceptions as a failed bake, then set `uWorldShadowReady=1` after `renderer.render`. WebGL framebuffer/allocation failure can produce GL error state without throwing. `GameApp.render` immediately hides the art-shadow mesh when readiness becomes positive, so that path could hide the fallback while publishing an unusable atlas. **Fixed and re-inspected:** atlas allocation now checks framebuffer completeness, retries smaller sizes, checks context loss before allocation and after render, and records a failure (`src/render/inkstorm/InkstormSunShadow.ts:83–118`). The focused tests exercise a 4096→2048 downgrade and failure at all attempted sizes. They do not inject context loss; those guards are verified by code inspection only.

2. **P2 — Settle failed preparation and clean up empty caster groups.** Originally, preparation and empty-result exits preceded the `try/finally`. A preparation exception therefore retried every frame, and empty bounds bypassed clone disposal. **Fixed and re-inspected:** the revision is settled before the callback, preparation and both empty-result exits are inside the protected block, and finalization handles nullable caster ownership (`InkstormSunShadow.ts:55–68,114–124`). Focused tests verify one callback invocation after repeated calls for the failed revision, and disposal of a zero-count instance mesh. A callback that throws before returning still owns cleanup of its partially created group; the atlas cannot release objects it never receives.

3. **P2 — Include bake submissions in frame telemetry, or report them separately.** Originally, the reset immediately before `post.render` erased atlas draw/triangle counts on startup, course replacement, and context recovery. **Fixed and re-inspected:** `renderer.info.reset()` is now the first operation in `GameApp.render` (`GameApp.ts:870–871`), before the atlas invocation. The governor's enclosing CPU work duration also includes that work (`GameApp.ts:647–657`). No steady-state FPS conclusion follows from this change.

4. **P2 resource policy gap — A successful 4K allocation still has a material mobile cost.** The initial atlas always selected `min(4096,maxTextureSize)` and was unrelated to the performance governor. RGBA8 color alone is 64 MiB at 4096², 16 MiB at 2048², and 4 MiB at 1024², plus a depth renderbuffer. Installed Three.js selects `DEPTH_COMPONENT24` for this target (`node_modules/three/src/renderers/webgl/WebGLTextures.js:274–278,1695–1718`); its actual device storage/padding is not measured here. Each in-bounds receiver fragment performs four atlas fetches (`InkstormSunShadow.ts:23–30`), and one initial bake draws all static placements at their full geometry detail. **Mitigation implemented and re-inspected:** `GameApp.ts:379` selects a 2048 ceiling when initial `window.innerWidth < 900`, otherwise 4096; framebuffer fallback can reduce the size to 1024. The test is viewport width, not device identity or portrait orientation, so a wide mobile/tablet viewport can still request 4096. The ceiling stays fixed for the app instance, avoiding resolution rebakes during normal adaptive-quality changes. Target-device memory and frame rate remain unverified.

5. **P2 — Align terrain lighting with the scenery atlas.** The original terrain default was `(-.42,.82,+.38)`, whereas the atlas, surface, road, and Cel material used `(-.42,.76,-.5)`. `GameApp` created the terrain without overriding that default, so terrain diffuse lighting, ridge highlights, and sparkles used a different sun direction from its received scenery shadows (`TerrainMaterial.ts:190–197,223,313,336`). **Fixed and re-inspected:** `src/render/terrain/TerrainMaterial.ts:389` now defaults to `(-.42,.76,-.5)`, matching the atlas. No additional test was added solely to assert a literal vector.

## Correctness and lifecycle checks

- **Packing is correct for the pinned Three.js version.** `three` is `0.185.1`. The receiver coefficients `[255/256,255/65536,255/16777216,1/16777216]` exactly equal this version's `UnpackFactors4`, including RGBA channel order (`node_modules/three/src/renderers/shaders/ShaderChunk/packing.glsl.js:10–30,56–58`). The all-white clear decodes to depth 1. Old Three.js examples with the opposite component order should not be applied to this code.
- **Projection is internally consistent.** The matrix is bias × orthographic projection × light view. Its direction `(-.42,.76,-.5)` now matches the surface, road, terrain default, and Cel lighting convention. Orthographic depth is linear, so bias divided by `(far-near)` is consistent. The installed renderer does not enable reversed depth (`src/render/app/createRenderer.ts:7–25`). Depth packing is written without color-output conversion in Three's depth shader (`node_modules/three/src/renderers/shaders/ShaderLib/depth.glsl.js:83–102`).
- **Caster instances are independent of racing-camera culling.** `InkstormWorld.createShadowCasters` builds instance matrices from retained full placements, rather than copying the visible near/distant batch counts (`src/render/inkstorm/InkstormWorld.ts:111–128`; compare `133–148`). Procedural structure clones include foundations, bridge, and vistas. The shader-displaced road and art-shadow ribbons are excluded; bridge structure still casts. Bounds are computed from the reconstructed group.
- **Normal clone disposal preserves world resources.** New family meshes use independent `instanceMatrix` buffers with shared geometry/materials. Three's `InstancedMesh.copy` also copies instance buffers for cloned structures (`node_modules/three/src/objects/InstancedMesh.js:182–194`). `InstancedMesh.dispose` releases instance attributes/VAO state, not the shared geometry (`node_modules/three/src/renderers/webgl/WebGLObjects.js:70–80`). The atlas's normal finalizer therefore does not dispose the world's geometry. World ownership remains in `InkstormWorld.dispose` and `setCourse`.
- **Startup and normal course replacement order are sound.** First `setCourse` can run before GLTF loading; successful loading calls `setCourse` again, populates retained placements, and increments `shadowRevision` (`InkstormWorld.ts:68–109`). `GameApp` bakes only once `loaded` is true. New road/vista materials created during a subsequent course replacement are bound during its new bake. Revision checks avoid a geometry bake on ordinary frames.
- **Existing craft selection does not create a late-receiver bug.** Receiver binding traverses hidden objects too. All craft-class modules are built in the constructor, and class changes toggle existing geometry rather than constructing new Cel materials (`src/render/objects/PodracerView.ts:914–943,1017–1046`). The current terrain levels also reuse one stable material. Newly added future materials would still need explicit atlas binding or a new revision; current code does not register arbitrary late receivers automatically.
- **Context recovery explicitly invalidates the atlas.** `GameApp.installContextRecovery` cancels the loop on loss, invalidates the atlas on restoration, and restarts rendering (`GameApp.ts:3609–3620` in the inspected tree). Stable shared uniform objects therefore become unready and receive the rebake. `GameApp.dispose` disposes the world and atlas before the renderer (`GameApp.ts:665–701`). These are code-path checks, not evidence that a physical device successfully restores the context.
- **Current render state restoration is appropriate to the caller.** The atlas restores active target, clear color/alpha, and `autoClear` in its finalizer. Three's `setRenderTarget` restores that target's configured viewport/scissor state (`node_modules/three/src/renderers/WebGLRenderer.js:2997–3027`); the current caller invokes this outside the post passes. The method does not preserve a nonzero cube face/array layer/mipmap level or arbitrary temporary viewport overrides. Those render-target modes are not used by the current `GameApp` call site and should remain an explicit unsupported integration case rather than a claimed current racing bug.

## Remaining quality boundaries

This is a single static directional atlas, not terrain self-shadowing or dynamic craft-to-world shadow casting. The camera fit uses the full caster world AABB transformed to light space. A distant vista can enlarge that fit and reduce effective resolution throughout the circuit; `receipt.texelMetres` exposes the resulting scale. Two-by-two comparison filtering, a depth offset of at least 0.65 world metres along the light, and receiver normal/up offsets intentionally limit contact detail. Reducing atlas size increases texel width and the texel-derived bias. Actual aliasing, detached contact edges, distant-vista impact, and small machinery readability need continuous visual inspection at each supported resolution.

Fallback art shadows are terrain-conforming translucent ribbons per authored placement (`src/render/inkstorm/InkstormShadows.ts:6–24`). They do not reproduce mesh self-shadowing, bridge/vista occlusion, or shade on moving craft. Their availability is a functional fallback, not evidence of matching image quality.

# Minimal two-client wreck feedback adaptation

Read-only design audit of `scripts/multiplayer.mjs` and existing combat observation code. No source change, browser launch, test run or native network evidence is claimed.

1. Reuse the owned Vite preview, two isolated contexts, real PeerJS room creation/join, ready/member checks, default race start, frozen build receipts and error collection. Open each native `[data-hud="room-panel"] > summary` before Create Room or code entry: it is now a collapsed `details`. Host creation removes fixed solo event rules, making the existing lap controls available. Set reduced motion to `no-preference` so the absence of a camera cut cannot be credited merely to the reduced-motion setting. Use DPR 1 for this bounded behavior check; do not claim a full-race performance result.
2. After synchronized start, focus the host viewport and hold ordinary S braking. Install read-only RAF observers on BOTH pages before the wreck; observe wall time, `simulationFrame`, `raceTime`, role/localRacerId, each identified racer's `galactic.wreck`, camera, pause state, HUD matte class and visible combat cue kind/title/age. Retain `performance.timeOrigin + performance.now()` for cross-page timing and ordinary frame deltas for per-page pace. Hold Shift with S after a real-time baseline, then release Shift immediately after the actual host-local wreck cue. Do not assign heat, hull, snapshots, events, clocks or game state.
3. Require the host's real `redline-explosion` and `wreck` events for racer `player`, with matching authoritative frame and cause. Require host-local WRECKED feedback. Require the guest's replica of racer `player` to enter wrecked and recover, while both room roles/members remain correct. Do not expect a local WRECKED badge on the guest for a different racer's crash: cue classification intentionally targets the local racer.
4. Around the actual event, require measurable pre-wreck, during-wreck and post-wreck simulation/race-clock progress near 1x on BOTH clients. Use sufficiently broad windows (at least 0.5–0.8 seconds, adequate samples and bounded observation gaps), report raw ratios, and account for the guest's discrete 20 Hz authority updates instead of expecting identical every-RAF step values. Retain host/guest step-gap and positional convergence checks after settling. Require no cinematic matte and no victim side-camera transition. A short under-sampled window is unavailable evidence, not a pass.
5. To prove GUEST-LOCAL feedback too, add a second ordinary input phase: focus guest, hold S + Shift, observe the host-authoritative `redline-explosion` and `wreck` for the guest's actual `onlineRoom.localRacerId` (normally `ai-vexa`), then require guest-local WRECKED feedback while clocks remain 1x and no cut/matte appears. The host's `recentEvents` is the authority evidence source. The guest restore path does not populate the public `galactic.recentEvents` list; use the host event plus guest replica/cue observations, not an assertion against a knowingly empty guest event list.
6. Save both raw observation traces, before/wreck/recovery screenshots, exact native bundle receipts, actual room role/member identities, event/cue timings, pace windows, convergence and errors. Release all keys in `finally`; stop observers; close pages/contexts/browser immediately; await owned preview exit with timeout and SIGKILL fallback. Write the final receipt after cleanup and require `browserClosed` and `serverExited`, rather than the current multiplayer script's fire-and-forget `server.kill('SIGTERM')`.

Minimal scope is a new bounded test case alongside the existing multiplayer smoke test. It should reuse bootstrap and helpers, omit unrelated mine/clipboard/vehicle-change assertions for this narrow gate, and leave existing coverage intact. Actual two-client feedback and clock acceptance remain unverified until that case runs.

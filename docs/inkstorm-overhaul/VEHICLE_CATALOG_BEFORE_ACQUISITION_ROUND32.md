## Standalone official API pipeline — separate archive workflow

The CLI now preserves schema 2 MCP source records. A catalog refresh or resume verifies the GLB SHA, size/header and original MCP download/export receipt hashes before retaining its downloaded status. It never decodes images to perform these checks. Verified MCP sources are skipped by the archive downloader. Source GLBs, raw archives, material studies, export families/variants, runtime integrations, driver inspections and added pilots have separate counters. Offline self-tests preserve those counters and their underlying receipts.

`python3 scripts/download-sketchfab-vehicles.py` uses only the official model metadata and `/v3/models/{uid}/download` endpoints. It reads an already-configured `SKETCHFAB_API_TOKEN` from the process environment and never prints or stores it. The default authentication scheme is `Token` for a personal API token. For an OAuth access token in that environment variable, use `--auth-scheme Bearer`.

```sh
# Offline inventory refresh; no account required and no network requests.
python3 scripts/download-sketchfab-vehicles.py --catalog-only

# Authorized download and verification, once the environment contains a token.
python3 scripts/download-sketchfab-vehicles.py

# Optional OAuth scheme, or one-model retry.
python3 scripts/download-sketchfab-vehicles.py --auth-scheme Bearer
python3 scripts/download-sketchfab-vehicles.py --uid 4eff45899ada40bb920c5c744663db90

# Offline archive-safety and receipt checks.
python3 scripts/download-sketchfab-vehicles.py --self-test
```

The pipeline prioritizes glTF ZIP, then GLB, then USDZ when returned by the official API. It preserves original archives, author/license receipts, model metadata, archive SHA-256 and each extracted file's SHA-256 under `assets/source/inkstorm/vehicles/<uid>/`. Temporary signed download links stay in memory and are never cached in receipts. Media requests use a separate client without the account Authorization header. API redirects cannot forward credentials to another origin.

ZIP extraction validates all member paths before writing. Absolute paths, traversal, Windows drive paths, links, special files, encrypted members and case-insensitive path collisions are rejected. Archive/expanded byte limits and file-count limits bound extraction. Downloads and receipts are written atomically; previously existing source copies are preserved. A rerun skips verified MCP source GLBs as well as archives whose receipts and extracted-file hashes still verify. Missing or changed source files become `verification_failed` while their source paths, prior statuses and receipts remain in acquisition history. Failed/incomplete model downloads restart at the model level; byte-range continuation is not claimed. The manifest is saved after every attempted model. Offline runs preserve 429 and other failure records. Real retry transitions append their prior records to `downloadHistory`; omitted public-search entries remain in `catalogueHistory` and recover their provenance if they reappear. Standalone CLI token availability is recorded separately from existing Blender MCP authentication evidence. Authentication rejection or rate limiting stops the batch without repeatedly hitting the API.

Exit code `0` means the selected operation completed (including offline catalogue-only runs), `2` means vehicle downloads remain blocked/pending, and `1` means invalid configuration or source metadata. The JSON summary distinguishes public results, candidate vehicles, exclusions, MCP source GLBs, raw archives, runtime/stylized completion and pending statuses.

The earlier CLI run passed its offline self-test and returned exit code `2` with 26 candidates pending a standalone environment token. That is historical CLI evidence, separate from the two subsequent successful authenticated MCP imports above. The current manifest distinguishes MCP-imported GLBs from raw archives and runtime-ready assets. The extended offline self-test exercises the real CLI entrypoint against temporary catalogs: two MCP sources, a legacy archive, 429/history/provenance retention, a verified-source resume with no network call, path/receipt swaps and source corruption. Both real MCP files were also verified read-only through the updated helper. No live download, credential handoff, browser/Blender call or actual-manifest catalog-refresh command was executed for this fix.

# Dotted silhouette diagnosis — private candidate only

The Sobel shader has a concrete stencil-classification defect that strongly fits the visible skyline stippling. Its normal/depth edge detector uses all eight neighboring samples, but its terrain/hull class lookup uses only the center and four axial neighbors. A diagonal-only silhouette fragment therefore receives generic full-strength ink instead of the suppression associated with the geometry that produced the edge. The numeric mechanism is confirmed; complete attribution of the actual screenshot still requires a matched runtime A/B.

I individually viewed [the actual V5 live-drive PNG](/Users/amir/Projects/PodRacing/output/gauntlet/round34-blockrunner-admission-v1/captures-material-framing-v5/live-drive.png). Small separated dark marks follow the large left cliff, the distant central settlement/rock skyline, the right pillar and outcrop, and low terrain against the sky. This is an implementation-aware review with prior project/source context, not a fresh blind critic. The tool displayed the 2160×1350 image at a reduced viewing resolution; no altered image or inferred GPU output was used.

## Bounded candidate

[Patch](sobel-complete-stencil-classification.patch) and [complete private candidate shader](candidate/sobelShader.ts) change only `src/render/post/sobelShader.ts` when later applied. They cache each of the nine packed depth/class samples, decode the same depth values, and take the class maximum over the complete stencil. The existing Sobel gradient math, local-depth denominator, thresholds, opacity, terrain/hull strengths and contact-shading function are unchanged.

The shader source expands to18 texture lookups in main, excluding contact shading, versus23 before caching. GPU compilers may already eliminate duplicate fetches; this is not a measured speedup. There are no additional render passes, draw calls, textures, targets, loops, AA modes or render-resolution changes. Physical terrain, simulation, vehicle geometry, scenery placements and LOD thresholds are outside the patch.

The [preparation script](prepare-candidate.py) requires the exact pinned source hash and writes only this private directory. `git apply --check` passed without applying the patch. No build, shader compilation, tests, browser, MCP call, live source edit, public asset change or performance run was performed for this task.

## Limits and next validation

Opaque [Inkstorm material output](/Users/amir/Projects/PodRacing/src/render/inkstorm/InkstormSurfaceMaterial.ts:299) has alpha1 and no stochastic discard; [LOD selection](/Users/amir/Projects/PodRacing/src/render/inkstorm/InkstormWorld.ts:225) switches an entire instance between detail batches without a screen-door fade. This does not implicate LOD dithering. Ordinary un-antialiased geometry edges and fine scan silhouettes can still alias after the classification fix. Their persistence would not disprove the specific stencil defect.

After the current frozen capture/benchmark is closed, root can review/apply this single-file candidate in a new checkpoint, then compile and capture a deterministic camera aimed at the same skyline. Match camera, render DPR and prepass scale; check scales1 and0.65 so the fix is not confused with a quality-level change. Compare world-sky fringes, near craft/control contours and terrain/prop contacts. A short moving segment should assess temporal behavior without claiming it from stills. Check renderer calls, texture/geometry/program resources and representative frame cost against the unchanged budget. Keep V8 contact-color and this outline change in separate comparison evidence.

The highest-class reduction already gives hull class precedence over terrain. Extending the stencil expands that precedence to diagonal neighbors, so mixed terrain/hull/generic boundaries warrant the targeted near-object comparison. No material-opacity reduction, smoothing of source geometry, distance fog increase or new AA pass is proposed.
